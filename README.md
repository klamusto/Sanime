# Sanime

موقع مشاهدة أنمي مبني على Next.js 16 + React 19 + Tailwind 4، يعتمد على واجهة
AnimeTom العامة كمصدر للمحتوى.

---

## ما الذي تم إصلاحه (ملخص سريع)

### 1) الحلقات الجديدة التي تعتمد على AnimeTom لم تكن تعمل

الـ API يعيد للحلقات الجديدة رابط HLS على بَكِت Cloudflare R2:

```
https://pub-497efadc5af745bfa313edcd382f0cd5.r2.dev/hls/<uuid>/master.m3u8
```

هذا الرابط **يرفض أي طلب لا يأتي من animetom.live** (يرجع
`401 – This bucket cannot be viewed`) ولا يرسل أي ترويسة CORS. لذلك يعمل على
الموقع الأصلي ولا يعمل أبداً من نطاق آخر — مهما كان المشغّل جيداً.

الحل: **وسيط بث داخل الموقع** — `src/app/api/stream/route.ts`:

- المتصفح لا يكلّم الـ CDN إطلاقاً، بل يكلّم موقعك.
- الخادم يعيد الطلب بهوية الموقع الأصلي (`Referer` + `Origin` + UA حقيقي).
- إن رد الـ CDN بـ 401/403 يجرّب هويات بديلة تلقائياً (Referer فقط، بدون
  ترويسات، أو نطاق مرآة مثل `cdn.animetom.live`) — `src/lib/fetch-media.ts`.
- يعيد كتابة ملف `m3u8` بالكامل (الجودات، المقاطع، مفاتيح التشفير، الترجمات)
  حتى تمر كلها عبر الوسيط.
- يدعم `Range` (التنقّل داخل الحلقة) ويضيف ترويسات CORS صحيحة.
- الروابط موقّعة بـ HMAC، فلا يمكن لأحد استخدام الوسيط كبروكسي مفتوح.

### 2) سيرفرات تعمل على الموقع الأصلي ولا تعمل عندك

- السيرفرات التي يعيدها الـ API بروابط فارغة تُحذف نهائياً بدل عرض أزرار ميتة.
- كل مصدر يُفحص من الخادم قبل العرض (`src/lib/servers.ts`): هل يعمل مباشرة من
  المتصفح؟ هل يحتاج الوسيط؟ هل يرفض العرض داخل إطار (`X-Frame-Options`)؟
- المصادر التي ترفض الإطار تُفتح عبر `/api/embed` الذي يزيل حواجز التأطير
  ويحوّل روابط `http://` إلى `https://` (لمنع حجب المحتوى المختلط).
- المشغّل ينتقل تلقائياً: نفس السيرفر عبر مسار آخر ← السيرفر التالي ← رسالة خطأ
  واضحة مع زر «فتح خارجياً».
- صفحة تشخيص جاهزة: `‎/api/diagnose?slug=one-piece&ep=1100‎` تخبرك لكل سيرفر
  لماذا يعمل أو لا يعمل.

### 3) إعادة تصميم كاملة — أبيض وأسود + أزرار زجاجية

- لوحة ألوان رمادية بالكامل (لا بنفسجي/نيون)، خلفية سوداء نقية.
- نظام أزرار «Liquid Glass» على طريقة iOS: `backdrop-blur` + حواف بيضاء خفيفة +
  لمعة داخلية + انكماش بسيط عند الضغط (`.btn`, `.btn-solid`, `.chip`, `.glass`).
- مشغّل جديد بالكامل: شريط تقدّم مع مؤشر التحميل، تحكم بالصوت، السرعة، الجودة،
  صورة داخل صورة، ملء الشاشة، اختصارات لوحة المفاتيح، متابعة من آخر لحظة،
  وتشغيل تلقائي للحلقة التالية.

### 4) تحسينات إضافية

- إصلاح روابط التحميل (كان الـ API يستخدم `text` بينما الكود يقرأ `name` فيظهر
  `undefined`).
- إعادة محاولة تلقائية عند فشل الـ API، وترويسات أمان، وخطوط عربية محلية
  (`@fontsource`) بدل ملفات مفقودة.
- هياكل تحميل (skeletons) لكل الصفحات، صفحة 404/خطأ بنفس الهوية، أيقونة جديدة،
  `sitemap`/`robots` يعتمدان على النطاق من المتغيرات البيئية.
- تقليل البيانات المرسلة للمتصفح في صفحة المشاهدة.

```bash

npm run dev
```

### متغيرات البيئة المهمة

| المتغير | الافتراضي | الوظيفة |
| --- | --- | --- |
| `ANIMETOM_API_BASE` | `https://api.animetom.live/api` | مصدر البيانات |
| `UPSTREAM_SITE` | `https://animetom.live` | الهوية التي ينتحلها الوسيط |
| `STREAM_SECRET` | قيمة افتراضية | توقيع روابط الوسيط — **غيّرها في الإنتاج** |
| `STREAM_PROXY` | `auto` | `on` = كل البث عبر خادمك، `off` = بدون وسيط |
| `STREAM_PROBE` | `1` | فحص السيرفرات قبل عرضها |
| `NEXT_PUBLIC_SITE_URL` | `https://sanime.app` | نطاق الموقع (SEO + الفحص) |

> ملاحظة عن الاستضافة: الوسيط يمرّر الفيديو عبر خادمك، لذا لو كنت على خطة ذات
> حد نطاق ترددي منخفض اجعل `STREAM_PROXY=auto` (الوضع الافتراضي) حتى لا يُستخدم
> الوسيط إلا للمصادر التي ترفض الوصول المباشر فعلاً.

## بنية المشروع

```
src/
  app/
    api/stream   ← وسيط البث (m3u8 + المقاطع + Range + CORS)
    api/embed    ← إعادة تقديم صفحات المشغّلات المحجوبة داخل إطار
    api/diagnose ← تشخيص سبب فشل أي سيرفر
    api/health   ← حالة الموقع والـ API
    watch/[slug]/[ep]  ← صفحة المشاهدة + المشغّل
  lib/
    config.ts      ← كل الإعدادات والمتغيرات البيئية
    fetch-media.ts ← جلب الوسائط مع تجاوز حماية الهوت‑لينك
    servers.ts     ← تنظيف وفحص وترتيب سيرفرات الحلقة
    stream-url.ts  ← توقيع روابط الوسيط + حماية SSRF
    animetom.ts    ← عميل الـ API مع التخزين المؤقت
```
